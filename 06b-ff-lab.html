Feed-forward, in the lab.

The capstone made three claims about the feed-forward network that are easy to say and easy to doubt: the little bend is load-bearing, most of the model's numbers live here, and the wide middle is a bank of overlapping detectors. Claims are cheap. Here we run each one and look at what actually comes out.

Experiment 1 — the bend

Claim: without the bend, stacking layers buys you nothing.

Test A · stack 8 straight-line layers, then check what they equal

Take 8 layers with random weights and no bend, run a vector through all of them — then separately multiply the 8 weight matrices into a single matrix and run the vector through that one matrix. If straight-line layers really collapse, the two answers should be identical.

8-layer output  =  [0.221, -0.1702, -0.0773, 0.1277 …]
1-matrix output =  [0.221, -0.1702, -0.0773, 0.1277 …]
difference between them  =  6.2e-16  (zero, to machine precision)

Eight layers were exactly one layer in disguise. However many you stack, with no bend they fold back into a single straight-line map.

Test B · same 240 random features, once without the bend and once with — fit a curve

Now give both versions the identical 240 random features and ask each to fit a wiggly target line, choosing the best combination of its features (a one-shot least-squares fit — no training loop). The only difference between the two is whether the bend is applied:

targetno bend → best it can dowith bend
fit error   no bend = 0.65  ·  with bend = 0.0

Same features, same fitting step. Without the bend the best possible answer is a straight line — because a combination of straight-line features is still a straight line. Add the bend and the exact same setup snaps onto the curve.

What this shows

The bend isn't a tuning detail — it's the only thing standing between "a deep model" and "a straight line wearing many coats." Every layer of depth is wasted without it. This is why the nonlinearity is the non-negotiable heart of the feed-forward network.

Experiment 2 — where the numbers live

Claim: about two-thirds of the model's learnable numbers sit in feed-forward, not attention.

Test · count the parameters of a real GPT-2, by part

No estimation needed — the sizes are fixed by the architecture. Attention is four square matrices (query, key, value, output): 4·d². Feed-forward is an up-projection and a down-projection through a 4× hidden size: 2·d·4d = 8·d². So per block, feed-forward is exactly twice attention. Counted for GPT-2 small:

And it holds at every size — the ratio is baked into the shapes. (The full totals below match the real published model sizes, which is the check that the arithmetic is right.)

Feed-forward always carries ~2× the weight of attention. Attention decides where to look; feed-forward is where the bulk of what the model has learned actually sits.

Experiment 3 — the wide middle

Claim: the widened hidden layer is a bank of detectors that fire selectively and overlap.

Test · push 12 real word vectors through the widen+bend, watch which units switch on

Feed twelve real GloVe word vectors into a random 200-unit hidden layer and record what fires. Each row below is one word; each column is one hidden unit; brighter means it fired harder:

Three things are visible in that grid, and each is one of the claims made real:

selective — only 31.2% of units fire for a given word (each word lights up its own sparse subset, not everything)
distributed — all 12/12 words get a distinct firing pattern (the identity is in the combination, not any one unit)
overlapping — unit #17 fires hardest for dog, cat, blue, red (animals and colours at once — no single clean meaning)

That last one is the key to the "you can't name a unit" point. And the reason it must be that way is a counting fact: 200 units that can each be on or off give 2200 possible firing patterns — an astronomically larger number than any vocabulary. The layer represents far more than 200 things because meaning is carried by which combination lights up, so distinct ideas are forced to share units.

Honest caveat

These weights are random, so the units here don't detect anything meaningful yet — what's real and visible even so is the mechanism: selective firing, a distributed code, and forced overlap. In a trained model the same structure fills with genuine detectors (a unit for "this is code", for "a quantity follows", for a specific idiom) — but still overlapping, which is exactly why reading individual units is hard. We're seeing the shape of the thing, before training gives it content.

The one-line aha

Run it and the three claims stop being assertions: the bend is the entire difference between depth and a straight line, two-thirds of the model's numbers really do sit in feed-forward, and its wide middle really is a bank of selective, overlapping detectors — visible even before training gives them meaning.
