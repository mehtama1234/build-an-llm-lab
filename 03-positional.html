Where am I?

Session 2 gave every token a vector for what it means. But there's a hole: the same token gets the same vector no matter where it sits — and attention (next session) treats the input as an unordered bag. So the model literally can't tell dog bites man from man bites dog. Position has to be injected. Real 4-D vectors below.

The hole

The token vector is position-blind

Look up the and you get one fixed vector — the same whether it's the 1st word or the 4th (Raschka Fig 2.17). The embedding table has no idea about order:

the @ pos 1+0.85-0.23+0.02+0.20same lookup
the @ pos 4+0.85-0.23+0.02+0.20→ identical

Why that breaks things

Order carries meaning. If two positions produce the same vector, and attention ignores order too, then dog bites man and man bites dog are the same input to the model — a disaster.

The fix

Add a second table: one vector per position

Make a second embedding, indexed by position (0,1,2,…), and add it to the token vector. Now the same token at different positions comes out different:

the @ pos 1+0.85-0.23+0.02+0.20++0.52-0.21-0.37+0.54=+1.37-0.44-0.35+0.74
the @ pos 4+0.85-0.23+0.02+0.20++0.42-0.09+0.28-0.38=+1.27-0.32+0.30-0.18

token + position = input vector — the two thes now differ. This sum is what actually enters the model.

The payoff

Now word order changes the input

Same three tokens, two orders. The token set is identical — but adding positions makes the input tensors differ (watch: bites is at position 1 in both, so its row is the same; only dog/man swap):

dog bites man
dogpos 0+0.25-0.13-0.12-0.73+-0.02-0.73-0.20-1.14=+0.23-0.86-0.32-1.87
bitespos 1+0.28+0.06+0.14-0.76++0.52-0.21-0.37+0.54=+0.80-0.15-0.23-0.22
manpos 2+0.83+0.08-0.19+1.01+-0.83+0.27-1.03-0.33=+0.00+0.35-1.22+0.68
man bites dog
manpos 0+0.83+0.08-0.19+1.01+-0.02-0.73-0.20-1.14=+0.81-0.65-0.39-0.13
bitespos 1+0.28+0.06+0.14-0.76++0.52-0.21-0.37+0.54=+0.80-0.15-0.23-0.22
dogpos 2+0.25-0.13-0.12-0.73+-0.83+0.27-1.03-0.33=-0.58+0.14-1.15-1.06

What GPT actually uses

These position vectors are learned — GPT uses absolute positional embeddings, a trainable table optimized during training (not the fixed sine-waves of the original transformer). There's also a relative family (encode distance between tokens). Either way: a second embedding, added on, so the model can feel order.

The one-line aha

A token vector says what; a position vector says where. Add them, and the model can finally tell order — because on their own, a bag of token vectors has none.
