The mathematics of a transformer.

One idea runs under the whole lab: a transformer keeps one running vector per word and, layer by layer, has the words read each other and refine themselves — until the last vector is read off as the next word's odds. This page is that spine — the big picture first, then the real math of every piece, in plain words, connecting the dots. No jargon left undefined.

Foundations

One running vector per word

The model's whole job is to predict the next token; it does this by maintaining and refining one vector per position, adding to it layer by layer rather than overwriting. This accumulation is the core mechanism — information compounds rather than getting destroyed.

\[p_\theta(x_t \mid x_1, \dots, x_{t-1})\]

The model outputs a probability for the next token given all previous tokens. θ (theta) are all the learned weights. Everything the transformer computes — every multiplication, addition, and softmax — exists to produce this one thing: a probability distribution over what comes next.

\[x^{(\ell)} = x^{(\ell-1)} + \text{sublayer}\big(x^{(\ell-1)}\big)\]

Each layer ℓ ADDS its output to the running vector instead of replacing it — this is called a residual connection. The input doesn't vanish; the new layer's work is piled on top. This means information computed early in the model can flow straight to the end, and nothing already learned is lost.

First, a token has to become a vector at all.

Sessions 1–2 · Tokens → meaning →

Turning a token into a vector

Tokens are just integer IDs (word 'cat' might be ID 2847). To compute with them they must become vectors, and the model must also encode WHERE each token sits in the sequence, since the attention mechanism is order-blind — it sees positions as just a set of items, not a sequence.

\[x_i^{(0)} = E_{t_i} + P_i, \qquad E \in \mathbb{R}^{V \times d}\]

Token ID t_i selects row t_i of an embedding table E (which has V rows for V tokens and d columns for d dimensions). P_i is a position vector added on; the sum is the starting vector for position i. Both E (the embedding table) and P (the position embeddings) are learned during training.

\[E_{t} = \operatorname{onehot}(t)^{\top} E\]

Looking up row t is mathematically the same as multiplying a one-hot vector (all zeros except a 1 at position t) by the table. This is just a reminder that embedding lookup is literally matrix multiplication — no magic, just choosing which row to read.

Now the vectors need to start sharing information across positions.

Session 4 · Attention →

Letting positions read each other

To use context, each position must pull in information from other positions in the sequence. Attention is a content-based weighted average — every position decides independently how much to read from every other, based on what they offer and what it's looking for.

\[Q = XW_Q, \quad K = XW_K, \quad V = XW_V\]

From the stream X (a matrix with one row per position), three learned projections W_Q, W_K, W_V produce three new matrices: Query (what am I looking for), Key (what do I offer to others), and Value (what I'll hand over if chosen). Each position gets its own query, key, and value vector.

\[A = \operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}} + M\right)\]

The dot product of query i with key j measures how relevant position j is to position i's needs — higher dot product means better match. Softmax turns each row into weights that sum to 1. M is a mask set to negative infinity for positions the token shouldn't read (like future tokens in language modeling), forcing their attention weight to zero.

\[\operatorname{Attention}(X) = A\,V\]

Each position's output is the attention-weighted average of all value vectors — a smart average, where the weights A tell you how much of each other position to mix in. Positions with high attention weights contribute more; low-weight positions contribute almost nothing.

\[\text{divide by } \sqrt{d_k}\ \Rightarrow\ \operatorname{Var}(q\cdot k)\approx 1\]

Dot products between d_k-dimensional vectors naturally grow larger as dimension increases (more numbers to add up). Dividing by √(d_k) shrinks the scores back to typical magnitude around 1, so softmax stays sharp and sensitive instead of collapsing into a hard maximum on one position.

One attention head is a single point of view — the model uses many in parallel.

Session 5 · Many heads →

Many points of view at once

One attention pattern captures one kind of relationship; running several in parallel lets the model track several kinds of relationship (subject-verb, adjective-noun, this-refers-to-that) simultaneously.

\[\operatorname{head}_h = \operatorname{Attention}(XW_Q^{h}, XW_K^{h}, XW_V^{h})\]

Each head h has its own small Q/K/V projections into a d/H-dimensional subspace, so each head attends over a different learned 'view' of the vectors.

\[\operatorname{MHA}(X) = \big[\operatorname{head}_1; \cdots; \operatorname{head}_H\big]\, W_O\]

The H head outputs are concatenated back to width d and mixed by a learned output projection W_O; splitting into H heads and recombining costs the same as one big attention but lets specialists form.

Attention only moves information around — something else has to do the per-word thinking.

Session 6 · Feed-forward →

Thinking about each word on its own

After gathering context, each position needs private computation; the feed-forward network processes every position independently, and it holds most of the model's parameters.

\[\operatorname{FFN}(x) = W_2\, \operatorname{GELU}(W_1 x + b_1) + b_2\]

Widen the vector from d to about 4d with W_1, pass through a smooth nonlinearity GELU, then project back to d with W_2; applied to each position separately; the nonlinearity is what lets it compute something a plain matrix can't.

\[W_1 \in \mathbb{R}^{4d \times d}, \quad W_2 \in \mathbb{R}^{d \times 4d} \;\Rightarrow\; \tfrac{2}{3}\ \text{of block params}\]

Because of the 4x widening, these two matrices are large — about two-thirds of the numbers in a transformer block live in the feed-forward part, which is why it's where much of the model's knowledge sits.

Attention and feed-forward are wrapped in two pieces that make deep stacks trainable.

Session 6 · One block →

One block: normalize, add, repeat

You can't just stack these operations deep — signals blow up or vanish; layer normalization and residual additions are what make a deep stack stable and learnable.

\[\operatorname{LN}(x) = \gamma \odot \frac{x - \mu}{\sigma} + \beta\]

Layer norm rescales a vector to zero mean and unit spread (μ, σ computed across its d entries), then applies learned scale γ and shift β; it keeps the numbers in a sane range at every step.

\[x' = x + \operatorname{MHA}(\operatorname{LN}(x)), \qquad x'' = x' + \operatorname{FFN}(\operatorname{LN}(x'))\]

A block does attention then feed-forward, each reading a normalized copy and ADDING its result back to the stream; the '+ x' is the residual connection that carries information (and gradients) straight through.

\[\frac{\partial x''}{\partial x} = I + (\cdots) \;\Rightarrow\; \text{gradients don't vanish}\]

Because of the additions, the derivative through a block always contains the identity I, so gradients flow cleanly back through dozens of layers — the reason very deep transformers can be trained at all.

Stack these blocks, add an entrance and an exit, and you have the whole model.

Session 7 · The whole model →

The whole model, entrance to exit

The full model is just the embedding, a stack of identical blocks, and a readout that turns the final vector into next-token probabilities — reusing the embedding table on the way out.

\[x^{(L)} = \operatorname{block}_L \circ \cdots \circ \operatorname{block}_1\big(x^{(0)}\big)\]

The starting vectors pass through L identical-in-shape blocks in sequence, each refining the running vector; depth is the same move repeated, each layer with its own learned weights.

\[\text{logits} = \operatorname{LN}_f\!\big(x^{(L)}\big)\, W_U, \qquad W_U = E^{\top}\]

A final layer-norm, then multiply by an unembedding matrix W_U to get one score (logit) per vocabulary token; GPT-2 ties W_U to the transpose of the input embedding E, so the readout reuses the same table — zero extra parameters.

\[p = \operatorname{softmax}(\text{logits})\]

Softmax turns the vocabulary-length score vector into a probability distribution over the next token; that distribution is the model's actual output.

Every weight in here started random — training is what made them mean something.

Session 8 · Training

Where the numbers come from

All those matrices begin as random noise; training nudges them, over and over, to make the real next token more likely — that is the entire learning process.

\[\mathcal{L}(\theta) = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta\big(x_t \mid x_{<t}\big)\]

The loss is the average negative log-probability the model assigned to the tokens that actually came next (cross-entropy); it is small only when the model consistently expected the true next token.

\[\theta \leftarrow \theta - \eta\, \nabla_\theta \mathcal{L}\]

Gradient descent — compute how the loss would change with each weight, then step every weight a little (size set by learning rate η) in the direction that lowers the loss; repeat on billions of tokens and the random matrices become a language model.

Once trained, we can open the model up and see what those vectors are doing.

Real-model experiments →

Reading the vectors inside

Because every layer writes to the same vector stream in the same coordinate system, we can inspect that stream mid-computation and even decode it early — this is what the lab's real-model experiments do.

\[\text{logit-lens: } \operatorname{softmax}\!\big(\operatorname{LN}_f(x^{(\ell)})\, W_U\big)\]

Apply the model's own readout to the running vector at an early layer ℓ, not just the last — you see the model's best guess as it forms, layer by layer; this works only because the stream stays in one consistent space.

\[x \;\approx\; \sum_{i} f_i(x)\, d_i, \qquad \#\text{features} \gg d\]

The model must represent far more concepts than it has dimensions d, so it packs them as many near-distinct directions d_i, with only a few active (sparse f_i) at a time — this crowding is 'superposition'. A sparse dictionary (autoencoder) recovers the individual features d_i.

Step back, and the whole transformer is one simple loop.

The mental model →

The whole thing in one breath

Every piece reduces to reading from and writing to one running vector per position, then reading off a probability.

\[\underbrace{\text{attention}}_{\text{mix across positions}} \;+\; \underbrace{\text{feed-forward}}_{\text{transform each position}} \;\;(\times L)\]

The only operation that moves information between positions is attention; feed-forward works on each position alone; a block is one of each, and the model is just L of these blocks on the shared vector stream.

\[\text{tokens} \to x^{(0)} \to \cdots \to x^{(L)} \to p_\theta(\text{next token})\]

Tokens become vectors, the vectors are refined by the stack, and the final vector is read out as a probability over the next token — that single pass, repeated one token at a time, is all a transformer does.

A transformer is not magic — it is one vector per word, refined and read out.
