Tokens read each other.

After embeddings and positions, each token vector still sits alone — it knows what it is and where it is, but nothing about the other words. Attention fixes that: every token looks at the others and pulls in information from the ones that matter to it. It's the heart of the transformer. Real attention weights below.

The problem

A vector alone can't resolve meaning

Meaning lives in context. In "the river bank" vs "the savings bank," the word bank should end up as two different vectors — but its embedding is the same for both. The only way to tell them apart is to look at the neighbors. That looking is attention.

The simplest form (Raschka §3.3) — real weights

Attend to whoever you're most alike

The barebones version: score every pair of tokens by how aligned their vectors are (a dot product), softmax each row into weights, and rebuild each token as a weighted blend of all tokens. That rebuilt vector has a name in the book — a context vector: an enriched embedding that now carries information about the whole sentence, not just the one word. Here's that computed on real 50-D vectors for a happy dog and a sad cat — each row shows what that word attends to:

The general form (Raschka §3.4)

Query · Key · Value — make the "looking" learnable

Raw similarity is fixed. Real attention learns three projections of each token so the model can decide what to look for — instead of "who's most alike," it's "who has what I need":

Query

what this token is looking for

Key

what each token offers

Value

what it hands over if attended to

score = Query · Key → scale by √dₖ → softmax → weights → context vector = weighted sum of Values. (The scaling matters: without it, large dot products push softmax to a near-step function and the gradients almost vanish — dividing by √dₖ keeps them healthy. That's why the book calls this scaled dot-product attention.) Q/K/V are trained, so the model learns useful attention patterns, not just similarity.

Two different "weights" — don't mix them up

Weight parameters (Wq, Wk, Wv) are the learned matrices — fixed once training ends. Attention weights are the softmax numbers in the grid above — dynamic, different for every sentence. Q and K produce the attention weights; V is what they're applied to → the context vector.

The GPT twist

You may only look left

In a generator, a token can't peek at words that come after it (that'd be cheating at "predict the next word"). So GPT applies a causal mask — it zeros out the future, keeping only the lower triangle. The same matrix, masked:

cat0.060.060.320.040.060.020.43

Upper triangle (·) is blocked. cat, the last word, may attend to everything before it; a, the first, can only attend to itself.

One more training-time detail (Raschka §3.5.2)

Dropout — hide some connections on purpose

During training only, GPT randomly zeros out a fraction of the attention weights (~10–20%) each step, then scales the survivors up to compensate. It forces the model not to lean on any single connection, which reduces overfitting. At inference it's switched off — every connection is live. It's a regularizer bolted onto attention, not part of the core idea, which is why we compute the clean weights above.

The one-line aha

Attention is each token asking "who here is relevant to me?" and rebuilding itself as a weighted blend of them — which is how a vector finally becomes context-aware instead of alone.
