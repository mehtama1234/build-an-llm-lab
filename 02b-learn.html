Where do the vectors come from?

The map from the last lesson looked designed — but nobody placed those points. In an LLM the embedding is a plain random table (nn.Embedding) that gets shaped by the model's one job: predict the next token. Below is a real embedding, trained from noise by exactly that objective, organizing itself.

The reframe

They start as noise — it's just a weight matrix

In Raschka's ch02, the embedding is created as nn.Embedding(vocab, d) — a block of small random numbers, one row per token. At that moment king and queen are nowhere near each other. It's not trained yet; it's just parameters, like every other weight in the network.

The force

Learned by predicting the next token

The whole model has one training signal (Raschka ch05, pretraining): given the tokens so far, predict the next one; measure the error with cross-entropy; backprop nudges every weight — including the embedding rows — to make the guess better. The embedding isn't trained separately; it rides the same gradient as the rest of the model.

embed(current token)→the network→P(next token)→error vs the real next token

…and the error flows back into embed(), moving that token's row. Do it billions of times.

Why this builds the map

To predict well, tokens that are followed by similar things must produce similar predictions — so they get pushed to similar vectors. king and queen sit in near-identical sentences, so their rows drift together. Meaning-as-geometry is a side effect of getting next-token right — nobody labels "these are similar."

One honest footnote

word2vec is the famous cousin — same force, different chore

You'll often see embeddings taught with word2vec / skip-gram, which trains a standalone table to predict a word's surrounding context (not the next token) — and it produces the same clustered geometry, because it's the same distributional force. An LLM doesn't run word2vec; it learns its embedding inside the model, from next-token prediction, jointly with everything else. Both routes, one idea: similar context → similar vector.

The one-line aha

The embedding is not a lookup someone designed — it's a random table trained by "predict the next token," and meaning falls out as geometry because same-context tokens must make same predictions.
