Everything, assembled.

You've built every part: words become numbers, numbers gain position, and a block lets them read each other and get refined. The assembly — start to finish

Entrance → 12 blocks → exit

The entire model is one straight path. A word goes in as a number, becomes a vector, flows up through 12 identical blocks that keep refining it, and comes out as a score for every word it might say next. Here is the real shape of the data at each step (for a 5-stage run on a short prompt):

token ids[7]the prompt as integers
↓
+ embeddings (token + position)[7, 768]each token becomes a 768-vector
↓
through 12 blocks[7, 768]same shape in and out — refined 12x
↓
final LayerNorm[7, 768]one last rescale
↓
x output head[7, 50,257]a score for every word, at every position

Notice the middle three: the shape [tokens, 768] goes into the blocks and comes out unchanged. That's the trick from Session 6 — a block never resizes the vector, it only improves it — which is exactly why you can stack 12 of them in a row.

Two surprises. A third of the model is just the word table (turning 50,257 tokens into vectors) — before any “thinking” happens. And the output head is free: it reuses that same word table (see below), so producing a score for all 50,257 words costs zero extra parameters.

Feed-forward is about twice the size of attention — the exact “two-thirds of a block” fact you measured back in Session 6, now confirmed in the assembled model. Multiply one block by 12 and you have the entire stack. Depth isn't 12 different tricks; it's the same move, refined 12 times, each layer with its own learned weights.
The clever exit — reuse the entrance

The output head is the input word-table, run backwards

To turn the final vector into word-scores, you need a 768→50,257 matrix — 38 million more numbers. GPT-2 doesn't store them. It reuses the token-embedding table: the same matrix that maps word → vector on the way in is used as vector → word-score on the way out. We checked in the real model — it's literally the same tensor in memory (yes). It makes sense: the space that defines what each word means is exactly the space you want to compare the final vector against. One table, both jobs, 38M parameters saved.

Why this matters
  • This is the entire architecture. Entrance (embeddings) → 12 identical blocks → exit (tied head). Every piece on this page is one you built from scratch; there is no other secret part.
  • Bigger models are this, scaled. GPT-3, GPT-4, and the models behind chat assistants are this same diagram with wider vectors, more blocks, and vastly more training — not a different idea.
  • You can account for every number. 124,439,808 parameters, each in a place you can name — word table, blocks, norms — and the output for free.
